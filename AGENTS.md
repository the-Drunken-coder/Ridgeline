# Ridgeline

Use the installed `t3-pstack` skills and their bundled workflows. Let PStack choose its working artifacts for the task.

Read the relevant project context before changing code:

- [README.md](README.md) for public contracts and package/playground validation.
- [CODE_CONVENTIONS.md](CODE_CONVENTIONS.md) and its applicable topic files for coding standards.
- [GLOSSARY.md](GLOSSARY.md) and relevant [ADRs](docs/adr/) for domain terms and accepted decisions.
- Existing `.scratch/<feature>/spec.md` files and linked tickets for approved feature requirements.
- The relevant `package.json` for current commands. The separate control lab is documented in [control-lab/README.md](control-lab/README.md).

Versioned feature specs own approved requirements. GitHub Issues own ticket status, discussion, and dependencies. Surface conflicts with an accepted decision before changing it. Open a PR or merge only when explicitly requested.
