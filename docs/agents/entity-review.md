# Reviewing entity ownership and callback histories

Use this reference when a change affects entity preparation, publication, callbacks, recovery, or disposal. It maps the owners to inspect and executable histories to attempt. Public contracts remain in [feature updates](../../README.md#features-and-updates), [entities](../../README.md#airborne-entities-and-attachments), [models](../../README.md#shared-models), and [readiness and diagnostics](../../README.md#readiness-and-diagnostics). Use the [glossary](../../GLOSSARY.md) for domain terms.

## Follow each result to its owner

An accepted update, successful preparation, and completed render can refer to different versions of the same feature ID. Compare each result with its own owner before treating it as current.

| Result | Owner and currentness | What replaces or retires it |
| --- | --- | --- |
| Accepted feature data | [FeatureStore](../../src/features.ts) validates and snapshots the complete batch. [Viewport upsert/remove](../../src/viewport.ts) passes accepted changes to entity preparation and native publication. Store reads expose accepted snapshots even when rendering fails. | A newer accepted snapshot replaces that ID; removal clears it. After a callback, resolve the current store entry again. An abort callback can reintroduce an ID while removal is still running. |
| Last successful prepared presentation | [EntityScene.build](../../src/entities.ts) commits `preparedModels`, placement state, position, and attachment geometry after checking feature identity and scene revision. The prepared feature, style, and effective model settings belong together. | Successful current preparation installs the next presentation. Failed styling retains the complete earlier presentation. Removal or replacement by a non-entity clears it. If a callback changes the revision while retaining the same feature, interrupted computation is queued again; this is distinct from retrying a failed style callback. |
| Terrain preparation | [Elevation](../../src/elevation.ts) owns placement/model area keys, area revisions, shared work, and abort controllers; [SensorCameraCoverage](../../src/sensor-camera-coverage.ts) owns camera coverage. Completion must still belong to the current area/work. | Changed required probes or area, model reference retirement, removal, provider reset, and destruction release the relevant ownership. Aborting may synchronously run a consumer callback. Recheck the requester before continuing cleanup; do not clear a replacement's work. Terrain readiness can requeue current geometry with stationary input. |
| Representation choice | [EntityScene](../../src/entities.ts) owns retained `choices`; [modelChoice](../../src/model-switching.ts) evaluates the documented distance/settings history. A frame keeps its proposed choices local until completed publication. | Inspect successful preparation and model-status changes for the documented reset conditions. Temporary terrain/renderer unavailability and off-screen culling must not erase a retained choice. Discarded preparation cannot reset the choice for restored earlier input. |
| Prepared model frame | [ModelLayer.prerender/render](../../src/model-layer.ts) owns the projection, renderer preparation, and frame. [EntityScene.prepareModelFrame](../../src/entities.ts) captures scene revision and configuration identity, then checks them after callbacks and before presentation/visibility commits. | Reentrant data, selection, preview, configuration, or model changes discard stale attempts. Preflight again before drawing if another layer changed the inputs. Context loss, layer removal, and destruction clear prepared frames. Camera motion supplies a new projection on the next frame. |
| Completed model drawing and picking | [ModelLayer.completed](../../src/model-layer.ts) publishes only a still-current frame after the native render event. EntityScene installs published representations and, only when models drew, their hit polygons and drawn terrain transform. `getEntityState` representation is a publication result, not a pixel-readiness assertion. | The next current completed frame replaces presentation and hit data. Context loss/destruction clears hits and retires drawing; replacement/removal must prevent an old frame from returning. Off-screen models may retain logical representation with no submitted geometry or pick box. |
| Native feature publication | [createFeaturePublication](../../src/feature-publication.ts) owns pending snapshots, failed IDs, submission tokens, and restoration tokens. [MapLibre publication](../../src/maplibre-feature-publication.ts) supplies the source identity. Viewport's published marker keys identify successfully prepared native fallback data. | A newer pending change wins for its ID. Source replacement, restoration retirement, and destruction invalidate older completion. Failed IDs wait for explicit retry or a newer change, using the current store entry. A loaded matching native marker and a completed model frame are separate readiness facts. |

The viewport owns listeners, the native map, and its container cleanup. Trace [destroy](../../src/viewport.ts) through DOM retirement before destroy listeners and deferred native resource removal during an active render. A synchronously mounted replacement owns its own canvas and map class. Cleanup from the old viewport must leave them intact.

## Attempt the histories relevant to the change

The names below are exact packaged-browser cases. [The packaged harness](../../tests/packaged/browser.spec.ts) runs them against a separately built consumer of the packed library. Pointer checks use its real browser-input bridge. Module checks help identify ownership failures; they do not establish pixels or native teardown.

| History | Executable case and observations to retain |
| --- | --- |
| A style callback throws after location, heading, pitch, roll, altitude, appearance, and model overrides change | [Model style failures retain the last complete pose until successful recovery](../../tests/model-frame-review.browser.ts) compares the full earlier model/attachment pixels, prepared altitude/time, and accepted data. It checks failed explicit retry, unrelated models, actual picking, and successful current recovery. |
| A valid configuration changes after failed preparation | The same style-failure case changes viewport distance/dead-zone defaults while retaining the earlier per-entity overrides. Check retained pixels and absence of a shared-renderer failure, then recover current settings with successful preparation. |
| A diagnostic changes selection or preview without replacing the entity | [Model diagnostics preserve entity computation through selection and preview callbacks](../../tests/model-frame-review.browser.ts) attempts unchanged selection, preview, and another entity's selection. Placement, icon fallback, and physical attachment pixels recover without a manual retry. |
| A diagnostic restores earlier input | The same diagnostics case restores heading from `MODEL_HEADING_MISSING` inside the dead zone. The established model choice and visible model survive the discarded unheaded preparation. |
| An entity callback replaces placement/appearance or removes the entity during a frame | [Model frame callbacks publish only current placement and appearance](../../tests/model-frame-review.browser.ts) compares a reentrant update with a directly accepted control, checks current frame attribution and actual picking, then attempts below-terrain replacement and removal. Neighbor geometry remains visible. |
| Terrain cancellation removes, replaces, or reintroduces the same ID | [Model switching preserves choices through temporary terrain and asset readiness](../../tests/model-switching.browser.ts) attempts removal during footprint abort, reference-change removal in a batch, and reintroduction during removal. It checks aborted ownership, the unaffected batch member, native source contents, and recovered icon/model pixels. |
| Sampling or completed-publication callbacks change configuration or replace an entity | [Model switching preflights failures and rejects reentrant stale frames](../../tests/model-switching.browser.ts) changes settings during sampling, removes/reintroduces an ID from `entitychange`, and checks current fallback pixels. It also covers GPU preflight/draw failure and explicit renderer recovery. |
| A computation callback destroys and remounts in the same container | The frame-callback case destroys twice, verifies immediate mutation rejection/DOM retirement, mounts a replacement, and checks that old uploads/draws stop without removing the replacement canvas or map class. |
| A destroy listener remounts during ordinary teardown or an active native render | [Viewport destruction preserves synchronous listener remounts](../../tests/model-frame-review.browser.ts) exercises both paths, waits for the replacement's readiness, and verifies repeated old destruction preserves its DOM. |
| Camera motion culls and later reveals a retained model | [Models cull off-screen bodies after enlargement and recover on camera motion](../../tests/model-frame-review.browser.ts) checks submitted geometry/counts, retained choice, actual picking, recovery, and a complete five-second quiet interval. |

Focused companions include [entity-scene tests](../../tests/entity-scene.test.ts) for preparation failures, style/sample replacement/removal, retained placement, and selection; [model presentation](../../tests/model-presentation.test.ts) for feedback geometry; [model switching](../../tests/model-switching.test.ts) for choice histories; and [registry tests](../../tests/models.test.ts) for registration replacement, cancellation, and resource retirement. Use the packaged cases above when reviewing their combined consumer behavior.

## Record what the review established

Pin the base/head and executed checkout, including uncommitted inputs, using the [tracker closeout record](issue-tracker.md#closeout-record). Record the attempted history, observed result, and relevant producer output. Distinguish inspection, executed module checks, and executed packaged-browser checks. A case listed here is available coverage, not evidence that the current revision passed it.

If a changed guarantee has no executable case, state the missing sequence and required observation explicitly. Add one focused behavioral regression at the agreed public seam only when coverage is missing; avoid duplicating these cases or weakening their pixel, picking, recovery, and quiet-period assertions. Report unexplained failures as gaps. Keep target-hardware acceptance and historical runs separate from current software verification.
