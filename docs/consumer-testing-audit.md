# Consumer journey audit

Audited September 29, 2026 for [consumer testing and parallel CI](../.scratch/consumer-testing/spec.md). The baseline had 87 packaged browser cases and four control-lab browser cases. This audit adds one packaged lifecycle case and keeps all existing cases and focused module tests.

The packaged suite builds and packs the library, installs the tarball into a separate consumer, checks its declarations, builds that consumer, and drives its production preview in Chromium. Its [case manifest](../tests/browser-cases.ts) identifies scenarios implemented in [the browser consumer](../tests/browser.ts). [Playwright](../tests/packaged/browser.spec.ts) supplies real mouse and keyboard input and records uncaught browser errors.

| Critical journey | Existing evidence | Audit decision |
| --- | --- | --- |
| Install, import, render | The consumer imports library exports and CSS from the installed tarball. `Queued features render with stable string IDs and click events` verifies rendering and real clicks. | Keep the package installation and production build on every shard. |
| Live updates and selection | `Incremental updates replace data without moving the camera` checks renamed and moved features, removal, styling, and retained selection together. `Style replacement preserves data and selection` covers basemap changes. | No duplicate case needed. |
| Mouse, keyboard, and focus | `Keyboard picker activation selects the chosen overlapping feature` applies consumer-owned selection. Picker refresh cases preserve focus as names, icons, and availability change. Inspector cases exercise native presses, Tab, Enter, and drag/undo interactions. | Keep real Playwright input across these paths. |
| Drawing lifecycle | `Drawing creates accepted features, owns clicks, edits with keyboard and survives style reload`, `Rejected drawing remains editable and cancellation preserves accepted data`, and `Accepted shape definitions survive consumer storage and viewport recreation` cover creation, acceptance, rejection, cancellation, editing, and reload. | Keep accepted feature and shape-definition assertions. |
| Terrain and camera recovery | `Incomplete custom camera terrain settles without polling and retries explicitly`, `A displayed camera failure removes only its coverage and retry uses current inputs`, and `Retained camera masks survive a style rebuild during terrain retry` cover unavailable data, explicit recovery, current inputs, and retained display. GPU allocation and synchronization cases cover renderer failures. | Existing controlled injection uses sampler and renderer interfaces and retains actual rendering and picking. |
| Destroy and remount | `Destroy during initialization, repeat destroy, then remount`, `Completed viewport releases DOM and rejects further mutation`, and destruction from diagnostics cover cancellation and cleanup. | Gap: a consumer elevation loader may finish after destruction while another viewport occupies the same container. Add `Late terrain preparation cannot affect a replacement viewport`. It checks cancellation, delayed completion, replacement data, one canvas, no late diagnostics, and real selection of the replacement feature with the same ID. |
| Control-lab consumer | Four [control-lab journeys](../control-lab/tests/controls.spec.ts) cover move orders and trails, Shift selection, Escape cancellation, armed drag/pan, pointer-centered wheel zoom, framing, fitting, and scene reset. | Gap: tests previously served Vite development output. The [configuration](../control-lab/playwright.config.ts) now builds and serves production output, refuses to reuse an unknown server, and keeps the same real input workflows. |

Focused module tests remain useful for geometry, drawing state, validation, publication, elevation sampling, and asynchronous ownership. They support the consumer journeys without replacing their package and browser boundaries.

These checks cover desktop Chromium with software WebGL. They do not establish Firefox or WebKit compatibility, physical GPU behavior, touch support, complete accessibility, or long-session memory behavior. Those remain separate follow-up work; this audit does not add speculative cases for them.
