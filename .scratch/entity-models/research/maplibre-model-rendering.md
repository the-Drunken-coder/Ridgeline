# MapLibre 6.11 entity model rendering research

Research date: 2026-10-03. Question: [Can MapLibre 6.11 draw entity models?](https://github.com/the-Drunken-coder/Ridgeline/issues/72), for the map [Entity models and representation switching](https://github.com/the-Drunken-coder/Ridgeline/issues/71). The answer feeds the ticket that chooses how Ridgeline draws and loads models; it does not make that choice.

## Answer

- **No native model support.** MapLibre GL JS 6.11.0 has no model layer, no glTF parser and no mesh primitive. The only first-party way to draw an arbitrary oriented mesh that shares depth with terrain is a `custom` layer with `renderingMode: '3d'`. The official model examples all use a custom layer plus three.js or Babylon.js for loading and drawing.
- **The existing entity layer is the right seam.** `src/entity-layer.ts` already uses the exact projection contract a model renderer needs: `projectTileFor3D`, the flat fallback blend for globe transitions, per-entity origins for precision, and nearest world copy selection. A model mesh can use the same contract per vertex, so flat, globe and the transition between them work without separate model matrices per projection.
- **What is missing is ordinary WebGL2 mesh work.** Indexed static meshes, per-instance attributes (instancing is core WebGL2), vertex array objects, textures, normals and simple lighting, depth writes and back-face culling for opaque surfaces, a per-frame screen-size scale, and model hit testing. MapLibre provides none of this, but its state handling around custom layers makes it safe to do.
- **Fixed screen size and picking are Ridgeline's job.** MapLibre supplies 64-bit matrices and the field of view each frame. Scale can be computed on the CPU from the entity's projected size, as `max(real size, fixed pixel size)`. `queryRenderedFeatures` never sees custom layers, so model hits must extend Ridgeline's own `pick`.
- **Limits are known and manageable.** WebGL2 is mandatory and already assumed. Globe depth precision is coarse at globe zooms, which matters only for ground contact there. Custom layers are dropped but not notified on Ridgeline's basemap rebuild, and are not restored after context loss.

## Version and evidence

Ridgeline pins `maplibre-gl` `6.11.0` and `@maplibre/maplibre-gl-style-spec` `26.4.4` ([package.json](https://github.com/the-Drunken-coder/Ridgeline/blob/61616e4819d5501d14ea157905b97808e4899866/package.json#L30)). The upstream tag `v6.11.0` resolves to `6d1df7b334ebb2411b918b50a8fbf68c81df2c9a` ([manifest](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/package.json#L4)). I compared a clone of that tag with `node_modules/maplibre-gl/src` after `pnpm install --frozen-lockfile`. They differ only in generated `*.g.ts` files, so every MapLibre link below points at the tag. Style-spec lines were read from the installed package and checked against the `v26.4.4` tag. The documentation site at maplibre.org shows the latest release rather than 6.11, so I used it only to locate examples. Every claim comes from tag source, tag examples or the tag changelog.

## 1. Native model support and extension points

- **No model layer type.** The style specification lists exactly `fill`, `line`, `symbol`, `circle`, `heatmap`, `fill-extrusion`, `raster`, `hillshade`, `color-relief` and `background` ([v8.json L767-L875](https://github.com/maplibre/maplibre-style-spec/blob/v26.4.4/src/reference/v8.json#L767-L875)). `custom` is accepted only as a runtime `CustomLayerInterface` object and cannot be serialized ([custom_style_layer.ts L341-L343](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/src/style/style_layer/custom_style_layer.ts#L341-L343), [style.ts L670](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/src/style/style.ts#L670)).
- **No glTF code.** A case-insensitive search of the tag's `src/` for `gltf`, `glb` and a `model` layer type finds nothing. `fill-extrusion` is the only native 3D primitive. It is an "extruded (3D) polygon" ([v8.json L820-L828](https://github.com/maplibre/maplibre-style-spec/blob/v26.4.4/src/reference/v8.json#L820-L828)), so it cannot draw an oriented, pitched or rolled mesh.
- **Official model guidance is custom layer plus a 3D engine.** The tag ships examples that load glTF with three.js `GLTFLoader` or Babylon.js inside a custom layer: [three.js](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/test/examples/add-a-3d-model-using-threejs.html), [three.js on globe](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/test/examples/add-a-3d-model-to-globe-using-threejs.html), [three.js on terrain](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/test/examples/adding-3d-models-using-threejs-on-terrain.html), [Babylon.js](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/test/examples/add-a-3d-model-with-babylonjs.html). The globe example builds a separate model matrix for each projection and switches abruptly when `projectionTransition > 0` ([L88-L111, L163-L173](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/test/examples/add-a-3d-model-to-globe-using-threejs.html#L88-L173)). Ridgeline's in-shader blend avoids that jump.
- **Other extension points do not draw depth-tested meshes.**
  - *WebGL style images* (`StyleImageInterface` with `renderWithWebGL`) render into a slot of the shared icon atlas. The interface says they make nothing possible that pixels could not ([style_image.ts L111-L135, L191-L200](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/src/style/style_image.ts#L111-L200)). They could pre-render a model view into an icon. They cannot place a 3D model in the scene.
  - `addProtocol` and `addSourceType` customize data loading, not drawing ([protocol_crud.ts L45](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/src/source/protocol_crud.ts#L45), [index.ts L183, L423](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/src/index.ts#L183)).
  - A custom layer's optional `prerender` runs in the offscreen pass and must bind its own framebuffer ([custom_style_layer.ts L273-L278](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/src/style/style_layer/custom_style_layer.ts#L273-L278), [draw_custom.ts L50-L60](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/src/webgl/draw/draw_custom.ts#L50-L60)). It is useful for GPU picking buffers, not for the main draw.
- **Upstream plans.** A quick search of maplibre-gl-js and maplibre-style-spec issues found no model layer proposal. This is unverified beyond that search and does not affect 6.11.

## 2. Drawing many oriented meshes with shared depth

### The custom 3D layer contract

- **Inputs every frame.** `render(gl: WebGL2RenderingContext, input)` receives `nearZ`, `farZ`, `fov`, `modelViewProjectionMatrix`, `projectionMatrix`, `shaderData` (`variantName`, `vertexShaderPrelude`, `define`), `defaultProjectionData` and `getProjectionData` ([custom_style_layer.ts L56-L169](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/src/style/style_layer/custom_style_layer.ts#L56-L169)). The prelude adds `u_projection_matrix` plus the projection's GLSL ([draw_custom.ts L20-L46](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/src/webgl/draw/draw_custom.ts#L20-L46)). `variantName` is the documented shader cache key ([L89-L95](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/src/style/style_layer/custom_style_layer.ts#L89-L95)), which Ridgeline already uses.
- **Units.** Under mercator, `projectTileFor3D(xy, z)` takes mercator `0..1` for x and y. Its z is conformal, so mercator units are the same in all three axes ([custom_style_layer.ts L142-L148](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/src/style/style_layer/custom_style_layer.ts#L142-L148); z scale at [mercator_transform.ts L987](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/src/geo/projection/mercator_transform.ts#L987)). Under globe, the elevation argument is meters above the sphere ([L149-L151](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/src/style/style_layer/custom_style_layer.ts#L149-L151)). That is why Ridgeline multiplies height by `meterInMercatorCoordinateUnits` only on the flat path ([entity-layer.ts L195-L203](https://github.com/the-Drunken-coder/Ridgeline/blob/61616e4819d5501d14ea157905b97808e4899866/src/entity-layer.ts#L195-L203)).
- **Matrix precision.** Mercator custom-layer matrices are passed as 64-bit floats, "to prevent precision loss ... very visible precision-artifacts and twitching for objects that are building-scale" ([mercator_transform.ts L976-L1000](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/src/geo/projection/mercator_transform.ts#L976-L1000)). In globe rendering, `fallbackMatrix` is the mercator matrix and `projectionTransition` is the live globe amount ([globe_transform.ts L452-L463](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/src/geo/projection/globe_transform.ts#L452-L463)). The transition value has only been live since 6.4.1 ([CHANGELOG L162](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/CHANGELOG.md#L162)).
- **Globe shader path.** `projectTileFor3D` converts mercator plus elevation to a point on the unit sphere, scales it by `1 + elevation / GLOBE_RADIUS`, and blends with the flat fallback during transition while keeping the matrix z ([_projection_globe.vertex.glsl L57-L96, L136-L148, L171-L174](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/src/shaders/glsl/_projection_globe.vertex.glsl#L57-L174)). Custom layers get these as plain uniforms, not MapLibre's uniform buffers ([L3-L9](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/src/shaders/glsl/_projection_globe.vertex.glsl#L3-L9)).
- **When globe is active.** Ridgeline's `globe` setting maps to MapLibre's `globe` preset ([viewport.ts L217](https://github.com/the-Drunken-coder/Ridgeline/blob/61616e4819d5501d14ea157905b97808e4899866/src/viewport.ts#L217)). The preset is vertical perspective up to zoom 11 and blends to mercator by zoom 12 ([projection_factory.ts L40-L48](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/src/geo/projection/projection_factory.ts#L40-L48)). Models close enough to be shown at real size are therefore almost always drawn on the mercator path, even in globe mode.

### Depth sharing with terrain

- **Shared depth.** A `3d` custom layer is drawn in the translucent pass with depth test `LEQUAL`, depth writes allowed, and the shared 3D depth range ([draw_custom.ts L61-L79](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/src/webgl/draw/draw_custom.ts#L61-L79), [painter.ts L488-L490, L581](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/src/render/painter.ts#L488-L490)). The terrain mesh uses the same depth mode ([draw_terrain.ts L46](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/src/webgl/draw/draw_terrain.ts#L46)) and is drawn when a draped stack ends ([render_to_texture.ts L18-L25, L229](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/src/webgl/render_to_texture.ts#L18-L25)). Custom layers are never draped, so models are occluded by hills and occlude each other through ordinary depth testing.
- **Globe without terrain.** MapLibre writes the globe's depth before the first non-opaque layer ([painter.ts L603-L619](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/src/render/painter.ts#L603-L619)), so models behind the planet are hidden.
- **Pass ordering.** Any 3D layer sets the opaque pass cutoff. Layers above it are drawn in painter order ([painter.ts L492-L501, L536-L543](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/src/render/painter.ts#L492-L543)). Ridgeline already pays this cost for `rl:entities`.

### Instancing and GL state

- **Instancing is available.** `drawElementsInstanced`, `vertexAttribDivisor`, vertex array objects and 32-bit indices are core WebGL 2.0 ([Khronos WebGL 2.0 specification](https://registry.khronos.org/webgl/specs/latest/2.0/)), and custom layers always receive a `WebGL2RenderingContext` ([custom_style_layer.ts L169, L286](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/src/style/style_layer/custom_style_layer.ts#L169)).
- **State is safe to change.** Before `render`, MapLibre unbinds its vertex array and resets cull face, active texture and unpack state. Afterwards it marks all cached state dirty, including programs, buffers, textures, the vertex array and its uniform buffer bindings ([context.ts L156-L211](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/src/webgl/context.ts#L156-L211)). MapLibre also unbinds any vertex array before it creates index buffers ([index_buffer.ts L24, L43](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/src/webgl/index_buffer.ts#L24)). A model layer can own its vertex arrays, textures and culling state. Its colors should match the documented premultiplied blend, or it should set its own blend function ([custom_style_layer.ts L257-L271](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/src/style/style_layer/custom_style_layer.ts#L257-L271)).
- **Instancing and precision pull against each other.** One instanced draw shares one matrix uniform. Ridgeline's precision comes from shifting the 64-bit matrix to each entity's origin on the CPU ([entity-layer.ts L27-L31, L161-L168](https://github.com/the-Drunken-coder/Ridgeline/blob/61616e4819d5501d14ea157905b97808e4899866/src/entity-layer.ts#L161-L168)). Two ways keep that precision:
  - Shift the matrix once per frame to a shared reference near the camera, such as the nearest copy of the map center. Upload each instance's 64-bit offset from that reference as 32-bit floats. Offsets stay small where models are visible.
  - Keep one draw per entity, as today. For 100 models this means about 100 draws times primitives per model.
  - Draw-call cost for either is not measured here.
- **Orientation in one shader for all projections.** Rotate model vertices by heading, pitch and roll in a local east-north-up frame in meters. Convert east and north to mercator offsets from the entity origin (`dx = east * m`, `dy = -north * m`, where `m` is `meterInMercatorCoordinateUnits` at the origin), then call the existing `projectPosition`. On globe, the sphere mapping makes the up axis radial automatically. glTF is right-handed with +Y up, +Z forward and units in meters, and front faces are counter-clockwise ([glTF 2.0 specification, coordinate system and units](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#coordinate-system-and-units)). One fixed axis swap maps it into east-north-up.

## 3. Fixed screen size, growth to real size, and picking

- **MapLibre has no screen-size helper.** `pixelsPerMeter` and `cameraPosition` exist on the transform but are `@internal` ([transform_interface.ts L291-L299](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/src/geo/transform_interface.ts#L291-L299)), and `Map` exposes no transform getter ([map.ts L596](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/src/ui/map.ts#L596)). The public inputs are enough, though: the 64-bit `defaultProjectionData` matrices, `fov`, the drawing buffer size and `MercatorCoordinate`.
- **Recommended scale computation (CPU, both projections).** Each frame in `render`, for each model entity, project its origin and a point one model radius away using the same path as `clipDisplayed` ([entity-layer.ts L262-L293](https://github.com/the-Drunken-coder/Ridgeline/blob/61616e4819d5501d14ea157905b97808e4899866/src/entity-layer.ts#L262-L293)). That gives the model's real on-screen radius `r`. Then set `scale = max(1, targetPx / r)`. At mid distance the model holds `targetPx`. Once its real projected size exceeds `targetPx` it is drawn at real size, with no discontinuity at the crossover. A smoothed blend between the two is also possible.
  - The projected origin's clip `w` is the view depth. Ridgeline can use it as the camera distance for representation switching without internal APIs.
  - `render` runs on every repaint, and camera moves repaint, so this needs no continuous loop.
  - 100 projections per frame is negligible on the CPU, though not measured.
- **Shader alternative.** Scale by the instance origin's clip `w` in the vertex shader, using the focal length `(viewportHeight / 2) / tan(fov / 2)`. This avoids per-frame instance uploads. But it needs a meters-to-world-pixels factor that differs between mercator and globe, and the CPU hit test would have to repeat the shader's scale exactly. Not verified.
- **Picking is fully Ridgeline's.** `queryRenderedFeatures` iterates only sources' tile managers and placed symbols ([style.ts L1637-L1700](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/src/style/style.ts#L1637-L1700)), so custom layer content is invisible to it. Options, all reusing the current terrain-occlusion check in `pick` ([entity-layer.ts L350-L410](https://github.com/the-Drunken-coder/Ridgeline/blob/61616e4819d5501d14ea157905b97808e4899866/src/entity-layer.ts#L350-L410)):
  1. **Screen-space bounds.** Project the instance's oriented bounding box (8 corners) with the frame's scale and test the convex hull. Cheap and predictable. Hits the empty space around thin shapes such as rotors and wings.
  2. **CPU mesh triangles.** Keep a simplified copy of each mesh's triangles on the CPU, prefilter with bounds, then run the existing triangle test. Matches the drawn silhouette. Costs memory and per-pick projection work, especially on hover.
  3. **GPU ID buffer.** Render instance IDs into an offscreen framebuffer in `prerender` or on demand, then `readPixels`. Pixel-exact, but that framebuffer lacks MapLibre's terrain depth, and `readPixels` stalls the GPU pipeline. Poor fit for continuous hover.
- **Reuse the drawn scale.** Whichever test is chosen must use the same scale and copy shift as the last rendered frame, as Ridgeline already does by caching `input` in `render` ([entity-layer.ts L110](https://github.com/the-Drunken-coder/Ridgeline/blob/61616e4819d5501d14ea157905b97808e4899866/src/entity-layer.ts#L110)).

## 4. Known limits

- **WebGL2 is mandatory.** WebGL1 support was removed in 6.0.0 ([CHANGELOG L252](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/CHANGELOG.md#L252)). The map requests only `webgl2` and throws `GPUInitializationError` otherwise ([map.ts L4217-L4241](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/src/ui/map.ts#L4217-L4241)). Model rendering adds no new requirement. MapLibre's default context has no antialiasing ([map.ts L503-L510](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/src/ui/map.ts#L503-L510)), but Ridgeline turns it on ([viewport.ts L101](https://github.com/the-Drunken-coder/Ridgeline/blob/61616e4819d5501d14ea157905b97808e4899866/src/viewport.ts#L101)), which helps model edges where MSAA is supported.
- **Depth precision near terrain.**
  - Mercator uses `nearZ = height / 50` pixels and a far plane just past the visible horizon ([mercator_transform.ts L742-L755](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/src/geo/projection/mercator_transform.ts#L742-L755)). The vertical perspective (globe) path uses `nearZ = 0.5` pixels and a far plane two globe radii out ([vertical_perspective_transform.ts L490-L499](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/src/geo/projection/vertical_perspective_transform.ts#L490-L499)).
  - My estimate assumes a 24-bit depth buffer (the context only asks for `depth: true`), a 1000 px tall viewport and the default field of view. Depth resolution at the screen center is then about 1 cm in mercator at zoom 16, but about 10 m on the globe at zoom 11. These are calculated, not measured.
  - Effect: at globe zooms, ground vehicles may z-fight with or sink into terrain. Above zoom 12 this is not an issue.
  - Separately, the terrain mesh is a 128-cell grid per tile ([terrain.ts L179](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/src/render/terrain.ts#L179)). `queryTerrainElevation` samples the DEM and includes exaggeration ([map.ts L1520-L1533](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/src/ui/map.ts#L1520-L1533)). The drawn surface and the sampled height can differ on slopes, so a ground model's base may float or clip. A small lift or a polygon offset may be needed. Not verified.
- **Globe float32 precision.** In the globe shader, mercator position is summed and converted to the sphere in 32-bit floats ([_projection_globe.vertex.glsl L59-L84](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/src/shaders/glsl/_projection_globe.vertex.glsl#L59-L84)), roughly 2 to 3 m of position resolution. That is below one pixel at globe zooms (about 38 m per pixel at zoom 11) and models there are enlarged. It should be invisible, but this is an estimate.
- **World copies and the date line.**
  - The custom layer receives only the zero-wrap world matrix ([vertical_perspective_transform.ts L1039-L1043](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/src/geo/projection/vertical_perspective_transform.ts#L1039-L1043), [mercator_transform.ts L976-L979](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/src/geo/projection/mercator_transform.ts#L976-L979)), so the layer chooses copies itself. Ridgeline already chooses each entity's nearest copy to the map center for drawing and picking ([entity-layer.ts L162-L168, L269-L272](https://github.com/the-Drunken-coder/Ridgeline/blob/61616e4819d5501d14ea157905b97808e4899866/src/entity-layer.ts#L162-L168)).
  - Models appear only near the camera, where at most one copy of an entity is plausibly on screen, so one copy per entity should suffice.
  - Building mesh vertices as local offsets from one origin means a model straddling 180 degrees is never split or stretched. On globe, `sin` and `cos` of the mercator x make the wrap continuous.
- **Basemap rebuilds.**
  - Ridgeline rebuilds the basemap with `setStyle(..., { diff: false })` ([viewport.ts L445](https://github.com/the-Drunken-coder/Ridgeline/blob/61616e4819d5501d14ea157905b97808e4899866/src/viewport.ts#L445)). That path calls `style._remove(false)` ([map.ts L2740-L2778](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/src/ui/map.ts#L2740-L2778)), which detaches layers without calling a custom layer's `onRemove` ([style.ts L1826-L1855](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/src/style/style.ts#L1826-L1855)). Only `Style.destroy` calls it ([style.ts L2183-L2187](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/src/style/style.ts#L2183-L2187)).
  - Ridgeline re-adds the layer after `style.load` ([entities.ts L201-L206](https://github.com/the-Drunken-coder/Ridgeline/blob/61616e4819d5501d14ea157905b97808e4899866/src/entities.ts#L201-L206)), and `onAdd` releases old GL objects first ([entity-layer.ts L71-L78](https://github.com/the-Drunken-coder/Ridgeline/blob/61616e4819d5501d14ea157905b97808e4899866/src/entity-layer.ts#L71-L78)).
  - The GL context survives `setStyle`. Uploaded model meshes and textures could therefore outlive a basemap swap if they are owned by a cache tied to the context rather than by the layer, which avoids a re-upload stall on every rebuild.
- **Context loss.** On context loss MapLibre destroys the style (running `onRemove`) and warns that custom layers "cannot be restored ... You will need to re-add it manually" ([map.ts L4257-L4289](https://github.com/maplibre/maplibre-gl-js/blob/6d1df7b334ebb2411b918b50a8fbf68c81df2c9a/src/ui/map.ts#L4257-L4289)). The model cache must be dropped on `webglcontextlost` and rebuilt from retained model bytes after `webglcontextrestored`.

## What `src/entity-layer.ts` would need

What already carries over:

- The projection prelude and variant cache.
- `projectPosition` with its flat/sphere blend.
- Per-entity origin precision.
- Nearest world copy selection.
- CPU projection for picking and the terrain-depth occlusion check.

What is new:

1. **Static model resources.** Per registered model: indexed positions, normals, UVs, base color texture or factor. Uploaded once into vertex arrays and textures. Today a single interleaved, non-indexed buffer is rebuilt on the CPU whenever anything changes ([entity-layer.ts L119-L137](https://github.com/the-Drunken-coder/Ridgeline/blob/61616e4819d5501d14ea157905b97808e4899866/src/entity-layer.ts#L119-L137)).
2. **Per-instance data.** Origin offset, heading, pitch and roll (or a rotation), the frame's screen-size scale, and a tint for selection or hover. The scale changes with the camera, so instance data needs a cheap per-frame update separate from mesh upload.
3. **An opaque draw state.** Depth writes on, back-face culling on, drawn before Ridgeline's translucent primitives. The current layer disables culling and depth writes for all draws ([entity-layer.ts L157-L160](https://github.com/the-Drunken-coder/Ridgeline/blob/61616e4819d5501d14ea157905b97808e4899866/src/entity-layer.ts#L157-L160)). Two options: a second custom layer below `rl:entities`, or an ordered opaque phase inside it.
4. **A lit model shader.** Uses the same `projectPosition`, with simple directional lighting so a mesh reads as 3D. Lighting look is a visual choice for the prototype.
5. **Model hits in `pick`**, using one of the options in section 3.
6. **Context-tied resource ownership** that survives `setStyle` and rebuilds after context loss.
7. **Vertical exaggeration.** `displayHeight` scales altitude by vertical exaggeration ([entity-layer.ts L48-L50](https://github.com/the-Drunken-coder/Ridgeline/blob/61616e4819d5501d14ea157905b97808e4899866/src/entity-layer.ts#L48-L50)). The spec must decide whether a model's own height is also exaggerated or only its placement.

One adjacent finding: entity icons are a `symbol` layer whose opacity already reads feature state ([viewport.ts L231](https://github.com/the-Drunken-coder/Ridgeline/blob/61616e4819d5501d14ea157905b97808e4899866/src/viewport.ts#L231)). Hiding an icon while its model shows could use feature state instead of republishing source data.

## Tradeoffs for choosing a drawing approach

These are inputs for the deciding ticket, not a decision.

- **Extend Ridgeline's custom layer with its own mesh renderer** (plus a small glTF parser or loader).
  - Keeps one projection contract, flat/globe blending, precision handling, world-copy logic and picking in one place.
  - No 3D engine dependency, and it fits the no-three.js constraint.
  - Ridgeline owns glTF subset support, lighting and materials, and must define which glTF features it accepts (for example static meshes with base color only).
- **Use a separate engine-style renderer inside a custom layer** (the official three.js or Babylon.js pattern, or a smaller WebGL helper).
  - Excluded for full engines by the map's constraint.
  - The examples snap between projections instead of blending, need `resetState` around every draw, and duplicate camera and picking math outside Ridgeline's existing layer.
- **Instanced draws vs one draw per entity.**
  - Instancing scales better and suits many copies of a few model types, but needs relative-to-reference offsets for precision.
  - One draw per entity reuses today's per-entity matrix shift unchanged and is simpler, at about 100 or more draws per frame. Neither is measured here.
- **CPU scale vs shader scale.**
  - CPU keeps rendering and picking identical and works in both projections, at the cost of a small per-frame instance upload.
  - Shader scale avoids the upload but must be replicated exactly in picking.
- **Picking.**
  - Bounds: cheap, coarse.
  - CPU triangles: exact silhouette, costs memory and CPU per pick.
  - GPU ID buffer: exact, but stalls the GPU and lacks terrain depth.
