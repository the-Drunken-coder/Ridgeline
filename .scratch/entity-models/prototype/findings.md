# Entity model prototype

Work for [Choose model appearance and switching behavior](https://github.com/the-Drunken-coder/Ridgeline/issues/76), under [Entity models and representation switching](https://github.com/the-Drunken-coder/Ridgeline/issues/71). Captures and measurements were made on 2026-10-04. The user then chose the appearance; the authoritative choices are in the [resolution comment](https://github.com/the-Drunken-coder/Ridgeline/issues/76#issuecomment-5976929100). Captures predate the approved replacement colors and combined ring plus brightening. This is a throwaway branch, `prototype/entity-models`, with no PR or merge.

## Run and compare

Run `pnpm dev:entity-models`. Choose `Four samples` to compare appearance, `100 + 1,000` for density, and `Tank on slope` for ground contact. Motion, size, distance, dead zone, swap, tint, model treatment and ground tilt all change live. The bottom switcher and left/right arrow keys cycle the three treatments. The measurements section exposes a triangle-load sweep and a context-loss button.

For a paused comparison, open `/?scenario=entity-models&modelView=samples&paused=1`. Append `&variant=ring`, `&variant=box` or `&variant=bright` to start with that treatment. All state is in memory. [Gallery](gallery.html) collects the screenshots and short recordings. [Model sources and attribution](model-assets.md) records acquisition, licenses, counts and hashes.

The workload has 25 copies each of the drone, tank, jet and boat, plus 1,000 icon entities. It moves through the existing `viewport.upsert` flow every 100 ms. The boat sits on land as a placement fixture. Its scene is not a water-navigation demo. The prototype keeps the four source credits in the sidebar.

## Browser and GPU limits

On 2026-10-04, the user chose to proceed with software smoke checks and record the hardware gap. The appearance discussion can proceed with the saved comparisons. Hardware workload measurements and a measured triangle guideline remain gaps.

The T3 desktop preview identified `ANGLE (Apple, ANGLE Metal Renderer: Apple M1 Pro, Unspecified Version)` in Chromium 152.0.7977.130, Electron 44.4.2. It disconnected before the playground rendered models. No model performance measurement or appearance capture was made on that GPU. There was no accessible discrete GPU and no `/dev/dri` device in the VM.

All saved appearance captures and browser numbers use Linux headless Chromium 153.0.8010.12 with `ANGLE (Google, Vulkan 1.3.0 (SwiftShader Device (Subzero) (0x0000C0DE)), SwiftShader driver)`. This is software WebGL, at device pixel ratio 1. The later captures use an 1,100 × 760 browser viewport and an 800 × 677 map canvas. The historical appearance capture used 1,280 × 900. These are smoke checks, not evidence of integrated or discrete GPU capacity.

A longer first capture ended when the browser closed during traversal. Both playground servers subsequently exited with SIGTERM. The cause was not established. Shorter captures completed. The moving software recording shows lag and trails around updated icons; the cause and hardware behavior were not established. The date-line view reported unavailable raw elevation over the ocean; that limits the terrain claim for that fixture. Historical observations are marked in their JSON rather than attributed to the current runtime revision.

## Triangle guideline

No defensible per-model triangle guideline was established. The instrumentation can run the same workload with original, 4× and 16× submitted geometry while preserving shapes and material counts. The largest sample then has 4,564, 18,256 and 73,024 triangles; the mixed workload has 172,850, 691,400 and 2,765,600 triangles.

On integrated and discrete hardware, record warmed flat and globe runs with moving entities and camera motion, including an icon-only baseline. Record the browser, GPU, canvas size, pixel ratio, visible instance counts, frame intervals, CPU pass, model submission and unique completed GPU queries. Select a workload budget before turning those results into a per-model threshold. Tessellation measures triangle cost for these materials, not every consumer model's texture and shading cost.

## Fidelity and scope

The prototype uses a separate instanced model layer, the shared entity projection, a pure in-house GLB parser, CPU screen-size scaling, and boxes routed through existing viewport picking. It keeps source bytes, parsed geometry and decoded textures, and hides symbols with feature state on the following frame. The registry and representation coordinator live in the playground controller as temporary stand-ins for viewport and entity-scene ownership. There is no public model API.

Main-thread parsing, simple local lighting and unsorted translucent parts follow the accepted approach. Production allocation-failure cleanup, diagnostics, lifecycle tests and the full parser validation suite are not completed by this prototype. Grouping, animation, drawing models, touch, automatic simplified distant models and production implementation stay outside the map's destination. Their absence is not newly discovered fog.

The remaining questions now live in [Choose the consumer model and color API](https://github.com/the-Drunken-coder/Ridgeline/issues/77), [Choose model picking, labels and attachment placement](https://github.com/the-Drunken-coder/Ridgeline/issues/78), and [Choose model browser and verification targets](https://github.com/the-Drunken-coder/Ridgeline/issues/79). [Measure model performance and correctness on target browsers](https://github.com/the-Drunken-coder/Ridgeline/issues/80) carries the hardware gap, triangle guideline and remaining verification work. It requires the browser-target and interaction decisions first. All are child tickets of the map, with native blocking relationships.
